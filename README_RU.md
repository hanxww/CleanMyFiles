## CleanMyFiles в одном предложении

**CleanMyFiles — локальная desktop-программа для анализа диска: она показывает распределение занятого места, проверяет точные дубликаты, помогает найти большие и старые файлы и отправляет в системную Корзину только то, что пользователь выбрал самостоятельно.**

В основе проекта простое правило:

> **Сначала понять. Потом чистить.**

Многие программы для очистки стараются показать максимально впечатляющее число: «Можно освободить 87 ГБ». CleanMyFiles оптимизируется под другое — **чтобы перед удалением было понятно, что именно вы видите и почему оно оказалось в списке.**

---

## Зачем это нужно

Переполненный диск заметить легко. Понять, **куда именно ушло место**, намного сложнее.

Можно вручную ходить по папкам в Проводнике. Можно довериться программе с кнопкой «Очистить всё». А можно часами искать копии одного и того же видео, забытые установщики, огромные загрузки и старые файлы проектов.

CleanMyFiles собирает эти задачи в один понятный процесс:

```text
Выбрать диск или папку
          ↓
Локально просканировать файловую систему
          ↓
Понять распределение места по типам и верхним папкам
          ↓
Проверить дубликаты, большие и старые файлы, кандидатов на очистку
          ↓
Самостоятельно выбрать ненужное
          ↓
Отправить выбранные файлы в системную Корзину
```

Для самого сканирования не требуется отправлять пользовательские файлы на удалённый сервер.

# Возможности

## Обзор занятого места

CleanMyFiles умеет сканировать корень диска или выбранную папку и превращать результат в понятную картину хранилища.

Программа показывает:

- объём проанализированных данных и количество файлов
- свободное / общее место на диске, когда эти данные доступны
- распределение по типам файлов
- агрегирование по папкам верхнего уровня
- крупнейшие найденные файлы
- оценку места, занятого лишними копиями дубликатов
- объём файлов, доступных для ручного review
- длительность сканирования и количество пропущенных элементов

Главный вопрос, на который должен отвечать Overview:

> **Куда делось место на диске?**

---

## Точный поиск дубликатов

CleanMyFiles не считает файлы дубликатами только потому, что у них одинаковое имя или размер.

Алгоритм работает поэтапно:

```text
все найденные файлы
        │
        ├── группировка по точному размеру
        │
        ├── быстрый BLAKE3 fingerprint
        │   (начало + конец файла)
        │
        └── полный BLAKE3-хеш содержимого
                  │
                  └── группа точных дубликатов
```

Так программа не читает каждый файл полностью без необходимости, но перед финальным подтверждением дубликата всё равно сравнивает полный хеш содержимого.

Полные хеши кэшируются на время текущей сессии по пути, размеру и времени изменения файла — повторный анализ неизменившихся файлов становится дешевле.

> [!NOTE]
> Даже байт-в-байт одинаковый файл не обязательно можно бездумно удалить: приложение может ожидать конкретную копию по конкретному пути. Поэтому окончательный выбор всегда остаётся за пользователем.

---

## Большие файлы

Раздел **Large files** собирает самые тяжёлые файлы из просканированной области в одном месте.

Для каждого элемента доступны:

- имя файла
- полный путь
- размер
- дата изменения
- категория
- открытие расположения в файловом менеджере
- ручной выбор для удаления

В текущей версии v0.2 интерфейс показывает до 100 крупнейших найденных файлов.

---

## Старые большие файлы

Иногда проще всего освободить место за счёт файлов, которые одновременно **весят много** и **давно не изменялись**.

Порог настраивается:

- большой файл: `25 МБ` / `100 МБ` / `500 МБ` / `1 ГБ`
- возраст: `90 дней` / `180 дней` / `1 год` / `2 года`

CleanMyFiles только показывает такие файлы для проверки — возраст сам по себе не означает, что файл ненужный.

---

## Отдельный обзор Downloads

Если внутри области сканирования есть папка `Downloads`, CleanMyFiles показывает её содержимое отдельным списком.

Там часто находятся:

- забытые установщики
- ISO-образы
- архивы
- экспортированные видео
- повторно скачанные файлы
- большие файлы, которые были нужны один раз

---

## Консервативные кандидаты на очистку

Раздел **Cleanup** специально построен осторожно. Он может показать файлы из распознанных cache / temp директорий и старые установщики в Downloads.

Но CleanMyFiles **не заявляет**, что каждый найденный элемент точно можно удалять.

> [!IMPORTANT]
> Кандидат на очистку — это предложение проверить файл, а не команда его удалить.

После сканирования ничего в этом разделе не выбирается автоматически.

---

## Прогресс сканирования в реальном времени

Большое сканирование не должно выглядеть как зависшее приложение.

Нативное Rust-ядро отправляет в интерфейс текущий прогресс:

```text
Сканирование
├─ количество найденных файлов
├─ обработанный объём
├─ текущий путь
└─ прогресс проверки дубликатов
```

Текущее сканирование можно отменить из интерфейса.

Тяжёлая работа с файловой системой выполняется вне webview-потока.

---

## Открыть файл до удаления

Любой найденный файл можно показать в нативном файловом менеджере.

На Windows CleanMyFiles позволяет перейти к файлу в Проводнике и посмотреть соседние элементы папки перед тем, как принимать решение об удалении.

# Модель безопасности

CleanMyFiles задуман скорее как **анализатор диска с инструментами очистки**, чем как оптимизатор с одной большой кнопкой.

| Правило | Поведение |
|---|---|
| **Никакого автовыбора** | После завершения сканирования файлы не отмечаются для удаления автоматически |
| **Сканирование только читает** | Сам процесс анализа ничего не удаляет |
| **Полная проверка дубликатов** | Финальная группа требует совпадения полного хеша содержимого |
| **Одна копия остаётся невыбранной** | `Select extra copies` оставляет минимум один файл группы для ручной проверки |
| **Ручной review очистки** | Cache / temp / installer-кандидаты требуют явного выбора |
| **Без рекурсивного обхода symlink** | Символические ссылки не используются для рекурсивного обхода |
| **Системная Корзина** | Удаление идёт через механизм Trash / Recycle Bin ОС |
| **Локальная обработка** | Пути и анализируемое содержимое обрабатываются локально desktop-приложением |

CleanMyFiles не пытается присвоить каждому файлу магический процент «безопасности удаления».

Это осознанное ограничение.

# Запуск из исходников

## Требования

### Windows

- Node.js **20+**
- Rust **stable-msvc**
- Microsoft C++ Build Tools с workload **Desktop development with C++**
- WebView2 (обычно уже установлен в современных Windows 10/11)

Если Rust ещё не установлен:

```powershell
winget install --id Rustlang.Rustup
```

После установки открой терминал заново и выбери MSVC toolchain:

```powershell
rustup default stable-msvc
```

Клонирование и запуск:

```powershell
git clone https://github.com/hanxww/CleanMyFiles.git
cd CleanMyFiles
npm install
npm run desktop:dev
```

Или используйте Windows helper:

```text
dev-windows.cmd
```

# Сборка Windows-установщиков

```powershell
npm install
npm run desktop:build
```

Или просто запустите:

```text
build-windows.cmd
```

Скрипт пытается самостоятельно найти Visual Studio Build Tools и инициализировать MSVC environment, если `link.exe` не доступен в текущем терминале.

После успешной сборки пакеты находятся в:

```text
src-tauri\target\release\bundle\
├── nsis\
│   └── CleanMyFiles_*_x64-setup.exe
└── msi\
    └── CleanMyFiles_*_x64_en-US.msi
```

> [!NOTE]
> Для MSI могут потребоваться дополнительные Windows-компоненты. NSIS setup.exe — наиболее простой формат для обычного распространения приложения.

# Чего CleanMyFiles специально **не делает**

Доверие важнее длинного списка функций.

Сейчас CleanMyFiles не пытается быть:

- очистителем реестра
- антивирусом
- программой для безвозвратного стирания файлов
- «ускорителем Windows»
- утилитой с кнопкой «удалить весь найденный мусор»
- гарантией того, что любой cache / temp файл всегда безопасно удалять

Если будущая функция потенциально может привести к потере данных, её модель безопасности должна быть понятна до релиза.

# Как помочь проекту

CleanMyFiles пока молодой проект, поэтому даже небольшие качественные изменения могут сильно повлиять на результат.

Особенно полезны:

- воспроизводимые bug reports
- тестирование на разных Windows-машинах и файловых системах
- проверка macOS / Linux
- profiling на очень больших деревьях файлов
- безопасные правила определения cache с подтверждёнными источниками
- accessibility-улучшения интерфейса
- небольшие и сфокусированные pull requests

Перед изменениями прочитайте **[CONTRIBUTING.md](CONTRIBUTING.md)**.

Уязвимости и чувствительные security-проблемы лучше отправлять по правилам из **[SECURITY.md](SECURITY.md)**, а не публиковать сразу в открытом Issue.
